# 参考作品对比与借鉴

两份参考都放在 `_refs/`（FreeCAD-main、vjmap-playground-main），本文件记录**看懂了什么、抄了什么、没抄什么、为什么**。
结论先行：FreeCAD 提供「约束与求解的工程标准」，vjmap 提供「Web CAD 的交互与交付形态」，本模块取两者之长，但按二维草图规模自研求解器，不引入两者的运行时依赖。

---

## 1. FreeCAD（Sketcher + planegcs）——约束与求解的标准答案

代码位置（解压后的 _refs）：

```
FreeCAD-main/src/Mod/Sketcher/App/Constraint.h          约束类型枚举（Coincident=1 … Symmetric=14, InternalAlignment=15）
FreeCAD-main/src/Mod/Sketcher/App/Constraint.cpp        约束的工程语义（驱动/参考、值、关联几何）
FreeCAD-main/src/Mod/Sketcher/App/planegcs/Constraints.cpp  每种约束的方程实现（9 万行量级）
FreeCAD-main/src/Mod/Sketcher/App/planegcs/GCS.cpp         求解器（LM / DogLeg / BFGS、稀疏 QR、冗余诊断）
FreeCAD-main/src/Mod/Sketcher/App/Analyse.cpp              求解后的自由度/冲突分析
FreeCAD-main/src/Mod/Sketcher/Gui/CommandConstraints.cpp   选择几何 → 施加约束的交互
```

### 抄了什么

| 借鉴点 | FreeCAD 做法 | 本项目落地 |
| --- | --- | --- |
| 约束分类 | 几何约束与尺寸约束分开，尺寸约束带驱动值 | 19 种：几何 13 + 尺寸 6，`CONSTRAINT_META` 统一元数据 |
| 约束方程 | 每个约束类实现 `error()` / 梯度 | `residuals(doc)` 返回残差数组，长度 = 方程数（如重合 2、对称 2） |
| 归一化 | 角度/方向类用三角与单位化，避免量级失衡 | 平行 `cross/(|d1||d2|)`、垂直 `dot/(|d1||d2|)`、点到线用有符号距离 |
| 诊断口径 | 求解后报自由度、冗余、冲突 | `自由度 = 变量数 − rank(J)`，`冗余 = 方程数 − rank(J)`，冲突按残差定位 |
| 交互范式 | 选几何 → 点约束 → 求解 → 状态反馈 | 左工具轨约束按钮 + 右侧诊断面板 + 画布约束标记 |

### 没抄什么（以及为什么）

- **不引入 planegcs 的 C++ 运行时**：它面向三维装配与大规模稀疏系统（GCS 里 LM/DogLeg/BFGS 多求解器 + 稀疏 QR），二维草图 < 100 变量用稠密 LM 足够，且能在浏览器里毫秒级跑完。
- **不做内部对齐（InternalAlignment）**：那是椭圆/双曲线等圆锥曲线的参数对齐，当前图元只有点/线/圆/弧。
- **不照搬块与三维草图的引用体系**：我们的图元用 id 直接引用，约束图更扁平，便于前端增量求解。

## 2. vjmap playground ——Web CAD 的交互与交付形态

代码位置：

```
vjmap-playground-main/src/01comprehensive_综合示例/05drawcadedit.js   CAD 图在线编辑（增删改 + 导出）
vjmap-playground-main/src/14_draw_图形绘制/                          绘图工具演示
vjmap-playground-main/src/15_measure_测量/                           测量演示
vjmap-playground-main/index.html                                     工作台布局与入口
vjmap-playground-main/js/vjmap/                                      SDK（min.js，闭源发布）
```

### 抄了什么

| 借鉴点 | vjmap 做法 | 本项目落地 |
| --- | --- | --- |
| 布局 | 左侧工具轨 + 中间画布 + 右侧属性/图层，顶栏放全局动作 | 同样的四区布局，CAD 制图配色（浅色纸面 + 深色顶栏） |
| 在线编辑 | 选中图元 → 拖动/改属性 → 立即生效，可撤销 | 选择/拖动实时求解、右侧约束列表改值即联动、命令栈撤销 |
| 捕捉 | 绘制时吸附底图与已绘点，显示捕捉提示 | 端点捕捉（12px）+ 捕捉标记与类型文字 |
| 交付 | 编辑结果导出 DWG/DXF 给下游 | DXF R12 导出（几何 + 标注分层），ezdxf 审计 0 错误 |
| 状态反馈 | 底部状态栏显示坐标/提示 | 状态栏坐标、求解消息、图元统计、变量/迭代数 |

### 没抄什么

- **不引入 vjmap SDK**：它是地图/矢量瓦片引擎（Cesium/Leaflet/MapTalks 多后端），我们的对象是工程草图，不需要瓦片与坐标系投影；引入反而带来授权与体积负担。
- **不做 DWG**：DWG 需要 ODA 转换器，比赛环境不可控；DXF R12 是通用下限。
- **不做多后端渲染**：单一 SVG 渲染器足以支撑矢量缩放与打印。

## 3. 与两者的差距（诚实清单）

| 能力 | FreeCAD | vjmap | 本项目 | 计划 |
| --- | --- | --- | --- | --- |
| 约束种类 | 20+（含圆锥曲线、内部对齐） | 无约束 | 19 | 补椭圆相关与自动约束 |
| 求解器 | 稀疏 QR + 多算法 + 冗余最小集 | 无 | 稠密 LM + 秩诊断 | 冲突最小集、增量求解 |
| 图元 | 点/线/圆/弧/椭圆/双曲线/样条 | DXF 全实体 | 点/线/圆/弧 | 接 OCCT 补 NURBS/椭圆 |
| 图层 | 完整图层与线型 | 完整图层 | 固定三层 | 图层管理 + 线宽 |
| 三维 | 完整 | 拉伸/三维图层 | 无 | 不在定位内 |
| 交付 | DXF/DWG/STEP/PDF | DXF/DWG | DXF R12（几何+标注） | 矢量 PDF、DXF 导入还原约束 |

---

## 4. 结论

- 评委问「你和 FreeCAD 什么关系」：**约束体系与诊断口径对齐 FreeCAD Sketcher，求解器按二维草图自研**，因此每一行求解逻辑都能讲清楚。
- 评委问「你和在线 CAD 什么关系」：**交互形态对齐成熟 Web CAD（vjmap 这类）**，但对象是参数化草图而非地图瓦片，交付是标准 DXF。
- 一句话：**FreeCAD 的工程标准 + Web CAD 的交付形态 + 自研的轻量求解器**。
